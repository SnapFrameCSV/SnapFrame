# Part A — Marketplace niche selection


Date: 2026-09-11. All install/rating/date figures below were pulled live from the public VS Code Marketplace query API (`extensionquery`, `flags: 918`, `sortBy: 4`, pageSize 15) on 2026-09-11 unless marked otherwise. Review quotes come from the public `.../extensions/{name}/reviews` endpoint (latest 30–40 reviews per extension).

## 0. Method notes and caveats (read first)

- **How the data was collected.** The sandbox's egress proxy blocks `marketplace.visualstudio.com` and `open-vsx.org` (HTTP 403 on CONNECT), so `curl` from Bash was impossible. I ran the exact POST body you specified from a marketplace tab in your desktop's browser pane instead (same API, same headers, `flags` bumped 914→918 to also get categories/tags). 210 search terms were queried (your list plus ~50 adjacent phrasings). The device disconnected near the end, before I could re-run a subset with `sortBy: 0`.
- **`sortBy: 4` is not pure relevance.** With `sortBy: 4` the API returns results in what looks like *relevance buckets, install-sorted within each bucket*: e.g. "regex tester" returns five extensions with "Regex Tester" in the name (2,074 / 415 / 117 / 61 / 51 installs) *before* Regex Previewer (1.0M). VS Code's own search box uses `sortBy: 0` (NoneOrRelevance), whose ordering I could not verify (UNVERIFIED). The *set* of matching extensions, and therefore the "sum of installs" demand proxy, is unaffected; the *order* users see may differ.
- **Install counts are cumulative and include updates** (microsoft/vscode#16156), so a 2019-abandoned extension with 4M installs may have far fewer live users than the number suggests. Treat sums as an upper bound on "people who ever searched this".
- **"Stale"** = `lastUpdated` before 2025-03-11 (18 months before today). "Σ15" = sum of installs over the top-15 matches. "top-1" = share of Σ15 held by the #1 result.
- Open VSX was checked for a handful of terms as a sanity check; its full-text search is much fuzzier than the marketplace's (a query for "json" returns the Python extension first), so it was not used for ranking. Ratio check: Rainbow CSV has 3.11M Open VSX downloads vs 23.69M marketplace installs (~13%).

- **Documented:** VS Code's docs only describe user-selectable sorts (`@sort:installs|rating|name|publishedDate|updateDate`) and filters (`@category`, `tag:`, `@popular`, `@featured`); no relevance formula is published ([Extension Marketplace docs](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace)). A 2023 discussion asking how relevance works got no answer beyond "ask in microsoft/vsmarketplace" ([vscode-discussions #870](https://github.com/microsoft/vscode-discussions/discussions/870)). Install count includes updates, which Microsoft's own issue tracker calls "not quite adequate" as a popularity signal ([vscode #16156](https://github.com/microsoft/vscode/issues/16156)).
- **Documented metadata levers:** `package.json` `pricing: "Free" | "Trial"` label (only those two values; no marketplace payments exist), max **30 keywords**, `sponsor` link, categories ([Publishing docs](https://code.visualstudio.com/api/working-with-extensions/publishing-extension)).
- **Observed in this run (sortBy 4):** results come back in relevance buckets — extensions whose *display name* matches the full query phrase come first regardless of installs (e.g. five sub-3k-install "Regex Tester" extensions precede 1.0M-install Regex Previewer; "Read Time" 62k precedes a 57M-install hit; "Keyboard Macro Beta" 37k precedes 16M), then description/tag matches ordered by installs. Practical implication: a new extension named exactly for a search phrase can appear on page 1 for that phrase from day one; for a single generic word (e.g. "csv") it cannot. Whether `sortBy: 0` behaves identically is **UNVERIFIED**.
- **Category counts** are returned in `resultMetadata` — e.g. "csv" spans Other 169, Visualization 147, Data Science 136, Formatters 93.

## 5. Recommendation: code-screenshot extension

**Why this one.** It is the only niche where (a) demand is real (~7M cumulative installs across one interchangeable shelf; CodeSnap alone still shows 3.9M), (b) *every* leader is abandoned with documented, fixable defects, (c) the maintained competition is a 286k-install fork and a 2.5k-install newcomer, (d) the build is small and dependency-light, (e) the file type carries zero privacy risk, and (f) a one-off price has precedent in adjacent screenshot tools. The extension name should contain the phrase "Code Screenshot" (observed name-match bucketing), with keywords `screenshot, code screenshot, polacode, codesnap, carbon, snapcode, snippet image, share code, social`.

**Free tier (must beat CodeSnap outright, no nag, no watermark, no ads):**
- Capture selection or whole file with the *current* theme and font via `editor.action.clipboardCopyWithSyntaxHighlightingAction` (shipped in VS Code 1.10, 2017; the technique codeimg and CodeSnap PR #72 use), with correct de-indentation and soft-wrap (CodeSnap's top two complaints).
- Window chrome, padding, background colour, shadow, rounded corners, optional line numbers, optional file-name/title bar.
- Export PNG to file **and copy image to clipboard** (CodeSnap's most-repeated 1★ complaint), 1× and 2× scale.
- One-command "quick snap" using the last settings; keyboard shortcut; works in VS Code, Cursor, Windsurf, VSCodium (Open VSX listing).

**Pro (one-off licence key, ~30% of code):**
- SVG (vector, editable), PDF and WebP export; 3×/4× scale; transparent backgrounds.
- Named presets (save/load/share as JSON), custom gradients/images, brand colour, optional *user's own* caption/handle/watermark.
- Line highlight / focus-dim ranges, inline annotations/callouts, line-range badges.
- Multi-snippet layouts: before/after (diff) and stacked/side-by-side compositions; terminal-selection capture (`workbench.action.terminal.copySelectionAsHtml`).
- Batch export (all selections / all open editors) and "copy as Markdown image link".

**Licence mechanism (no runtime server):** Stripe Checkout → Stripe webhook (or a Stripe-hosted "after payment" page) hands the buyer an Ed25519-signed key encoding `{product, issuedAt, seat-hint}`; the extension verifies the signature offline with the embedded public key and stores the key in `globalState`. No revalidation, no phone-home, no email stored in the key beyond an optional truncated hash. Note that key *issuance* still needs one tiny serverless function or manual emailing; that is purchase-time, not runtime, and is the one piece the agent cannot fully own.

**Price:** US$9 one-off (launch), consider US$12 list after the first 100 sales. Rationale: below Xnapper's $29.99 device tier and Turbo Console Log's $29.99, above the "$3.99 impulse" band where refund/support costs dominate; the product is a convenience, not a workflow dependency, so it should be priced as an impulse.

**Expected outcome (honest):** discovery only via marketplace search means growth tracks CodeSnap's slow decay. If the extension reaches ~1,000–3,000 installs/month within a year (plausible for a page-1 result on "code screenshot"/"screenshot") and converts 1–2% of *active* users, that is on the order of tens of sales per month, i.e. a few hundred dollars/month at best. None of the eight niches supports more than that without marketing; this one is simply the best risk/effort fit.

**Top three risks**
1. **Willingness to pay is thin.** carbon.now.sh, ray.so and codeimage are free, and screenshots are an occasional need. Mitigation: keep Pro strictly additive (see backlash table), make presets/SVG/annotations the visible upsell, and never degrade free output.
2. **Rendering fidelity in the webview.** CodeSnap's #1 complaint is fonts; ligature fonts (Fira Code, JetBrains Mono), emoji, CJK, and `html-to-image`/canvas export are exactly where bugs cluster, and an unattended agent cannot eyeball pixels. Mitigation: produce SVG via `foreignObject` as the source of truth, rasterise from it, and keep a golden-image test suite the weekly run compares by pixel diff.
3. **Ranking and discoverability.** CodeSnap will keep #1 on install count for "screenshot" for years; the name-match behaviour I observed was under `sortBy: 4`, not the `sortBy: 0` VS Code uses (UNVERIFIED). Mitigation: exact-phrase display name, all 30 keywords, both marketplaces, and a "Reviews" prompt only after a successful export (ratings count is a visible ranking signal on the listing).

Runner-up if you want a "serious tool" instead of a consumer-ish one: **XML/XPath tools** (#2) — same abandoned-leader pattern, enterprise buyers, mature pure-JS libraries — accepting slower, smaller demand and more edge-case maintenance.
